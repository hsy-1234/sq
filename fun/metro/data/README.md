# 武汉地铁数据文件格式

数据文件采用“一行一条记录、空格分隔”的文本格式，支持 `#` 注释和空行。
中文站名可以包含空格，但为了解析简单，建议站名中不要出现连续空格。

## 记录类型

```text
STATION  <站编号> <中文站名>
LINE     <线路编号> <线路名>
SEG      <线路编号> <区段号> <0普通|1环线>
STOP     <线路编号> <站编号> <到下一站km> <到下一站min>
TRANSFER <站编号> <换乘分钟>
```

### STATION

定义一个物理站点。站编号建议使用 `S001` 这种固定宽度编号，方便排序和查表。

```text
STATION S001 洪山广场
```

### LINE

定义一条运营线路。线路编号建议使用 `L02`；线路名可以写 `2号线`。

```text
LINE L02 2号线
```

### SEG

开始一个连续区段。`区段号` 从 1 开始；`loop=1` 表示环线，最后一站接回
第一站。普通线路通常只有一个区段；有支线的线路可以写多个 `SEG`。

```text
SEG L02 1 0
```

### STOP

紧跟在某个 `SEG` 后面，表示该区段的一个停靠点。`到下一站km` 和
`到下一站min` 是到下一站的里程和运行时间；普通区段末站写 `0 0`。
环线的末站写“回到首站”的里程和时间（闭环边），不要写 `0 0`，
否则末站到首站的边没有权重。`loop=1` 仍然用于标记这是环线。

```text
STOP L02 S001 1.6 3
STOP L02 S002 2.2 4
STOP L02 S003 2.8 5
STOP L02 S004 0 0
```

### TRANSFER

可选记录，覆盖某个换乘站的默认换乘时间（默认 4.0 分钟）。

```text
TRANSFER S001 4.0
```

## 换乘站判定

同一个 `STATION` 编号出现在多条线路的 `STOP` 记录中，就自动视为换乘站。
例如 `S001 洪山广场` 同时出现在 2 号线和 4 号线，系统会为它建立两条
线路节点之间的换乘边。

## 环线与支线

- 环线：`SEG L12 1 1`，站序按运行方向排列，最后一站通过 `loop` 接回首站；
  末站 `STOP` 的里程和时间就是这条闭环边，不能写 `0 0`。
- 支线：同一线路写多个 `SEG`，每个区段有自己的站序；共线站点用相同
  `STATION` 编号。
- 同一区段内不要重复写同一站点；否则 `metro_validate()` 会报格式错误。

## 数据文件

- `wuhan_metro.txt`：全量数据，13 条线路、298 座物理站点、352 条
  `STOP` 记录（12 号线为环线，37 站 + 1 条闭环边）。站名相同即合并为
  换乘站，共 49 座换乘站，最大换乘线路数 3。
- `wuhan_metro.sample.txt`：只包含 2 号线和 4 号线的 6 个站点，用于先把
  解析器、建图和查询流程跑通。
- `wuhan_metro_stations.csv`：站点编号、站名、经纬度、所属线路（UTF-8 BOM，
  可直接用 Excel 打开）。
- `wuhan_metro_lines.csv`：线路编号、站数、是否环线、官方里程、估算运行时间。

## 全量数据的来源与估算

站序、站名和经纬度取自高德地图武汉地铁页面
<https://ditu.gaode.com/ssr/subway/wuhan-4201> 及 13 条线路的详情页。
高德地铁总图 JSON 漏掉了 7 号线的“余彭塆”，全量文件按详情页补齐。

官方页面没有逐站里程，因此：

- 站间距 = 相邻站经纬度的球面直线距离 × 该线校准系数；
- 校准系数 = 线路详情页“全程 X 公里” ÷ 该线直线距离之和；
- 每条线路的 `STOP` 里程合计与官方里程一致（如 2 号线 60.4 km、
  7 号线 83.1 km、12 号线 60.0 km）；
- 运行时间按平均旅速 34 km/h 估算，四舍五入到分钟，最小 1 分钟。
